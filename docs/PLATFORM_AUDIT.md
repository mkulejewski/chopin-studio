# Stage 1 platform audit

Baseline `c34c0a7`, 2026-11-19. This follows the [domain refactor](REFACTORING.md).

| Layer | Current owner and coupling at baseline | Stage 1 boundary |
| --- | --- | --- |
| Musical core | `midi_files` uses Mido for codecs and mixes journal reading with export staging. `performance`, `velocity`, `recognition`, `segmentation`, `symbolic`, `passages`, `tempo`, `musical_comparison` and the deterministic part of `teacher` consume files or evidence. `learning_definition`, `learning_matching`, `learning_staves` and `reference_review` already isolate the musical rules. | Reuse existing codecs, note and score types, fingerprints, matching, evidence, and lesson modules. Use the current message dictionary at the event boundary. |
| Application services | `recorder` contains hardware discovery, capture queues, writer and pedal commands. `organisation`, `segment_analysis`, `timeline`, `assessment`, `progress`, `live`, `learning` and `learning_profiles` already have separate ownership. `jobs` mixes orchestration with FluidSynth discovery, subprocess and Linux resource limits. `microphone` mixes ALSA startup/stop and signal handling with audio metadata, compaction and analysis. | Inject driver/host facilities. Keep connection selection, capabilities, playback scheduling, capture, profiles, background work, evidence, retention and recovery shareable. |
| Devices/integration | `recorder` and `api/settings` use Mido ports and discovery state directly. `hardware_audio` couples output, ALSA, capture exclusion and score segment export via its route. `microphone_capture` supervises arecord. `api/audio` discovers Linux executables and soundfont paths. | Linux owns RtMidi ports, ALSA process supervision, FluidSynth/tools, soundfont discovery and stereo playback capture. Shared playback uses generic output, bounded cancellation waits and cleanup. |
| Lifecycle/storage | `app` mixes HTTP lifespan, Learning ticking, disconnect saves and idle exit. `__main__` and `scripts/launch.py` own process lock, loopback listener, XDG, logs, browser launch and shutdown. Store mixes SQLite with XDG lookup; journal, uploads, audio retention and reports assume same-filesystem replacement and file/directory synchronization. | Explicit host-owned data root and path-backed durability contract. Keep Store schema/services portable. Move service lifetime out of HTTP; Linux composition owns XDG, process lock, desktop and idle policies. File pickers/import/export stay at the host/transport edge. |
| Transport and UI | `app`, `api/`, `practice_api`, `learning_api` adapt services. Learning selection is in the router. `frontend/src/api.ts` uses same-origin HTTP; App and status hooks coordinate connection and workspace state. Learning owns visibility pause/heartbeat, and score and fullscreen rely on browser DOM/PDF.js. | Preserve routes and React behavior; lift Learning selection and shared lifetime out of handlers. Linux continues to host the compiled frontend and enforce loopback/origin checks. |

Ownership after wiring runs from the Linux and HTTP composition edges to shared services and their protocols. Shared services call injected device and file facilities. Musical modules consume ordered journal data and their existing reference/evidence structures. Store remains SQLite and assumes app-owned, local paths; native document URIs cross a later host's import/export boundary via staging. Tests can replace the ports, clock inputs, audio and durable I/O without hardware, a browser, or a server.
